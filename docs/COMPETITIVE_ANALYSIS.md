# Сравнительный анализ: Island Engine vs Industry Standards

Этот документ объясняет архитектурный выбор в пользу собственного ECS-движка на Java 21 и его место среди современных игровых технологий.

## 1. Island Engine vs Unity (DOTS)

| Характеристика | Island Engine | Unity DOTS |
| :--- | :--- | :--- |
| **Философия** | Simulation-First (Логика > Графика) | Visualization-First (Графика > Логика) |
| **Тип ECS** | Pure ECS (нативный с нуля) | Hybrid ECS (надстройка над старым ядром) |
| **Управление памятью** | Zero-GC + SoA на Java 21 | C# Memory Management + Burst Compiler |
| **Изоляция** | Строгая (Java JPMS / Modules) | Слабая (скрипты имеют доступ ко всему) |
| **Вес рантайма** | < 10 MB (JAR) | > 200 MB (Player) |

### Почему не Unity?
1. **Overhead:** Unity тянет за собой рендер-пайплайны, физику мешей и аудио-стек, которые не нужны для "чистой" симуляции. В Island Engine каждый цикл CPU тратится на биологические алгоритмы.
2. **Инкапсуляция:** Благодаря JPMS (`module-info.java`), плагины физически не могут получить доступ к внутренним структурам движка (`.internal`), что гарантирует стабильность ядра.
3. **Сложность DOTS:** DOTS в Unity все еще находится в состоянии активной трансформации и имеет высокий порог вхождения. Наш ECS-стек лаконичен и спроектирован под конкретные задачи RTS/TBS.

## 2. Сравнение с Java-аналогами (LibGDX / Ashley)

Island Engine отличается от классических Java фреймворков следующим:
- **Project Loom:** Использование виртуальных потоков для параллельной обработки чанков мира без накладных расходов на переключение контекста ОС.
- **Встроенная предметная область:** Наличие готовых модулей `island-nature` и `island-simcity` делает его специализированной платформой, а не просто библиотекой рендеринга.
- **Data Locality:** Реализация SoA (Structure of Arrays) напрямую в движке для минимизации кеш-промахов процессора.

## 3. Целевые жанры и применимость

### ✅ Рекомендуется (Идеально)
- **RTS (типа "Козаки"):** Обработка армий в 10,000+ юнитов за счет ECS и пакетной обработки данных.
- **TBS (типа HoMM):** Сложные системы городов и экономики, модульность через компоненты.
- **Симуляторы колоний (типа RimWorld):** Глубокое моделирование агентов и их потребностей.

### ❌ Не рекомендуется
- **FPS / Шутеры:** Требуют latency < 1ms и специфических физических движков.
- **AAA 3D проекты:** Текущий стек ориентирован на 2D/Изометрию и высокую плотность логики.

## 4. Итог: Инженерный выбор
Island Engine — это выбор в пользу **предсказуемости, производительности и архитектурной чистоты**. Мы используем мощь современной Java (21+), чтобы дать разработчику контроль над данными, который обычно доступен только в низкоуровневых C++ движках, сохраняя при этом безопасность и скорость разработки на Java.
